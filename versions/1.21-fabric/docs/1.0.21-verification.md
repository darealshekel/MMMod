# MMMod 1.0.21 / Minecraft 1.21 Verification

Scope: Minecraft 1.21, Fabric only. Other version ports were stopped at the user's request and are not part of this release. No website deployment or sync-access policy change.

## Checks

- Gradle unit/regression suite: 274 tests, 272 passed, 2 skipped, no failures or errors.
- Real isolated Minecraft 1.21 integrated-server smoke: `MMM_RELIABILITY_SMOKE_PASS`.
- Smoke covers instant mining acknowledgement, cancelled mining/external removal, server rollback, mining longer than ten seconds, mixin audit, live scoreboard totals, vanilla/MMM chat focus and typing, rejected MMM draft retention, advancements screen, rank estimate HUD, account switching, and advancement outbox save/reload.
- Timer regression covers restoring session IGT and retaining an already-running countdown when another world's checkpoint is restored.
- Sync regressions cover world/account/scope queue keys, newer queued replacements after an older failed request, saving while HTTP is blocked, and retained progress during partial acknowledgements.
- Personal-state regression checks separation, switch-back restoration, unchanged credentials, and preservation of unattributed legacy data.
- Final release is built without the smoke source set. Packaging checks verify embedded version and absence of test probe classes.
- GitHub upload verification compares downloaded jar and source archive SHA-256 hashes with the prepared local files before publication.

Local logs: `reports/fix-1.0.21/reference-verified-runtime.log` and `reference-release-final.log`.

## Boundaries

- No live production sync was submitted as a test; tests do not alter public mining records.
- Runtime testing uses Fabric's isolated development environment, not every possible third-party mod combination.
- Existing skip cases remain skipped; runtime checks provide separate game integration coverage.
- Legacy estimates without receipts cannot be retroactively attributed to worlds. They keep their migration behavior; new local mining is reconciled using persisted world-scoped receipts.
- Historical data already mixed by an old client is not automatically deleted or redistributed. Unknown-owner legacy data is preserved for explicit recovery.
- A server accepting a chat message while losing both its HTTP reply and live event can still require a retry; client persistence is not a claim of server-side exactly-once delivery.
